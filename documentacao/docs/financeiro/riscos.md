# Riscos

## 12. Riscos e mitigação

| Risco | Probabilidade | Impacto | Mitigação |
|---|---|---|---|
| Meta API travar verificação do cliente | Alta | Médio | Avisar no kickoff; checklist de documentos antes de cobrar setup; alternativa: provider não oficial (com aviso de risco) |
| Bot responder errado e queimar reputação | Média | Alto | FAQ fechado, guardrails, handoff fácil, 7 dias de acompanhamento |
| Cliente não pagar mensalidade | Média | Médio | Cobrança recorrente automática desde o dia 1; pausa do serviço |
| Suporte virar emprego extra | Alta | Alto | Limite contratual de ajustes; janela de suporte; escopo por escrito |
| Dependência de 1 nicho | Média | Médio | Template replicável para 2º nicho após case |
| Você não ter tempo | Média | Alto | Máx. 2 noites/semana + 1 dia de fim de semana; 3 pilotos no teto |
| Concorrente cobrar mais barato | Baixa | Baixo | Concorrer em entrega e resultado medido, não em preço |

## 34. Riscos específicos do modelo completo

| Risco | Mitigação |
|---|---|
| Suporte consumir o tempo que a automação precisa | Teto de horas por contrato + fila com SLA + 70% remoto |
| Ser chamado para tudo que é "computador" | Escopo escrito do que **não** atende |
| Quatro frentes abertas ao mesmo tempo | Máx. 2 camadas por trimestre |
| Automação quebrar e virar sua culpa | Monitoramento incluído + SLA + relatório |
| MEI estourar o teto de faturamento | Acompanhar faturamento mensal e migrar para ME/Simples antes do limite (verificar teto vigente) |
| CNAE incompatível com suporte + dev + SaaS | Validar CNAE e atividade permitida antes de abrir; pode exigir ME, não MEI |
| Cliente de suporte sem potencial de projeto | Regra: todo cliente de suporte precisa ter projeto possível em 90 dias |
